## Xee (Xee³) 開啟圖片時的預設 UX 行為 — 調查結果

以下是能從公開來源確認的事實，其他部分標記「查不到」。

### 1. 視窗是否自動貼合圖片大小？
- **有相關選項**：Preferences 中有 **"Resize window automatically"**（自動調整視窗大小）設定。啟用時，切換圖片會讓視窗跟著新圖片的長寬比重新調整。
- 使用者回饋（Wakaba 論壇）明確描述 Xee「always resizes its window to the image's aspect ratio」。
- **預設值查不到**（論壇貼文只提到「I have … resize window automatically … turned on」，無法確認是預設或使用者手動勾選）。

### 2. 圖片超過螢幕的行為
- 由 **"Fit on screen"** 與 **"Always fit opened images on screen"** 兩個相關偏好控制。
- **"Always fit opened images on screen"** 的預期行為：讓開啟的圖片以 fit-to-screen 縮放顯示。
- **已知限制/bug**（GitHub gco/xee issue #415）：這個選項在「從 Finder 開啟新檔」有效，但在 **browsing（用鍵盤翻頁）時不會重新套用**——新圖片會沿用前一張的縮放等級，而不是重新 fit。
- Fitting options 可設為 **horizontally / vertically**（水平或垂直方向 fit）。
- 另有 **"Shrink to fit"** 旗標：v3 的行為與 v2 略有差異（v2 可作為 toggle，v3 不再是簡單 toggle）。

### 3. 預設縮放：actual size 還是 downscale to fit？
- **查不到官方文件明確說明「open 時的預設」**。
- 但從論壇與 issue 語境推斷：Xee 的設計預期是搭配 "Always fit opened images on screen" + "Resize window automatically" 使用，也就是**傾向 downscale to fit** 而非 actual size。
- 另有 View → **Automatic Zoom** 子選單，內含「remember the zoom level」選項；"shrink to fit" 若開啟會覆蓋這個記憶行為。
- Superuser 上有問題專門在問「怎麼從命令列讓 Xee 用原始尺寸打開」，解法是開啟後用 AppleScript 送 `Cmd+0`——**反面佐證預設不是 actual size**。

### 4. 相關偏好設定名稱（確認存在的）
- `Fit on screen`（動作/按鈕）
- `Always fit opened images on screen`（Preferences 選項）
- `Resize window automatically`（Preferences 選項）
- `Shrink to fit`（旗標，行為在 v2/v3 間有變化）
- `Fitting options`：`horizontally` / `vertically`
- `Scaling quality`：`low` 等等
- `Immediately switch to fullscreen mode`（開啟即進入全螢幕）
- View → `Automatic Zoom` 子選單（含 remember zoom level）
- View → `Always Open in Full Screen`

### 查不到 / 沒有明確來源
- 各選項的**出廠預設值**（on/off）——官方頁面 `theunarchiver.com/xee` 沒有偏好文件；只能從論壇貼文推測部分使用者組態。
- 圖片超過螢幕時，是「視窗 clamp 到 screen 再縮圖」還是「視窗開全螢幕大小」的**精確幾何邏輯**——原始碼層級的行為官方沒有文件；`gco/xee` 是原始 repo 但沒公開的說明文件描述這段。
- Xee 是否對「小於螢幕的圖片」也放大 fit——一位使用者明確**要求**「只縮不放」，暗示現行行為可能會放大，但沒有官方確認。

### `resizeToFitImage(_:center:)` — `Cee/Controllers/ImageWindowController.swift:264-322`
Clamp 邏輯：
1. **上限**：`requestedSize = min(size, screen.visibleFrame.size)`（`:270-273`）— 用 `screen.visibleFrame`（非 `frame`），會扣掉 menu bar / Dock。
2. **下限**：`effectiveMinContent = min(effectiveMinimumContentSize(), visibleFrame.size)`，再 `targetSize = max(requestedSize, effectiveMinContent)`（`:274-282`）。因此小圖時視窗**不會**縮到比 min content 還小；圖片比 min 還小的話會留出空邊，圖片不會被拉大。
3. `center: false` 保持原視窗中心（`:294-299`）；`center: true` 才置中到 `visibleFrame`。
4. 最後用 `clampedWindowOrigin` 保證整個 frame 落在 `visibleFrame` 內（`:301-304`、`:344-354`）。

### 何時觸發 window hug？— `shouldResizeWindowToMatchImage()`


`scheduleResizeToFitAfterZoom` 有 gate（`:1775-1787`），`resizeWindowToFitZoomedImagePreservingCenter` 用 `displayedSize = imageSize * magnification + statusBarH`（`:1803-1808`）當請求尺寸。全螢幕時直接 return。

## 2. `alwaysFitOnOpen` 開/關差異（開新圖）

進入點：載入完成後呼叫 `applyFitting(for:)`（`ImageViewController.swift:551`、`:660-684`）。

- `alwaysFitOnOpen == true`（預設值 true，`ViewerSettings.swift:10`）：

  - `scheduleResizeToFitAfterZoom(...)`（`:683`）在 `shouldResizeWindowToMatchImage()` 為 true 時 resize 視窗貼合。因為 `alwaysFitOnOpen` 本身即會讓 `shouldResizeWindowToMatchImage()` 回 true → **視窗會 hug 顯示後的圖**。

- `alwaysFitOnOpen == false`：

### 關鍵回答

**「alwaysFitOnOpen=true 時，小圖會被放大到填滿視窗嗎？還是視窗縮小貼合圖片維持 100%？」**

→ **預設是視窗縮小貼合圖片、圖片維持 100%**。因為 `FittingOptions` 預設 `stretch = false`，`FittingCalculator` 對小於 viewport 的圖不會放大（`FittingCalculator.swift:22-23`、`:33-39`），`fittedMagnification` 回傳 1.0。接著 `scheduleResizeToFitAfterZoom` 將視窗尺寸設為 `imageSize × 1.0 + statusBarH`，並由 `resizeToFitImage` 在 `effectiveMinimumContentSize()`（下限 300×300，`Constants.swift:7-11`）與 `screen.visibleFrame`（上限）之間 clamp。若使用者手動打開 Stretch H/V，才會拉大填滿視窗。

**「大圖開啟時視窗與 zoom 各是什麼？」**（`alwaysFitOnOpen=true`）

→ zoom = `viewport.width/imageW` 與 `viewport.height/imageH` 兩者的較小值（`FittingCalculator.swift:42-48`）；視窗 = `imageSize × 該 mag + statusBar`，被 `screen.visibleFrame` clamp 到最多整個可用螢幕。若 clamp 生效，`resizeWindowToFitZoomedImagePreservingCenter` 之後會用 `refitMagnification` 再校正一次以吻合實際 viewport（`ImageViewController.swift:1813-1819`）。

## 4. `effectiveMinimumContentSize()` 與最小尺寸 clamp

### 定義 — `ImageWindowController.swift:233-260`
```

  Constants.minWindowContentWidth (=300),
  window.contentMinSize,

```
`fittingSize` 主要來自 status bar 等 Auto Layout 內容；CLAUDE.md 提到隱藏 view 也會影響 `fittingSize`，故 StatusBarView 在 minimal 模式會 deactivate 水平約束以避免它污染下限（`Cee/Views/StatusBarView.swift` — 見 CLAUDE.md 記錄）。

### 使用場景
1. `ensureUsableWindowSize()`（`:220-231`）：視窗比 min 小 → 直接還原成 `defaultWindowSize` 並置中。
2. `resizeToFitImage(...)` 下限（`:274-278`），但同時再 `min(...visibleFrame)` 讓 min 不會超過螢幕。
3. `effectiveWindowResizeMinMagnification()` — `ImageViewController.swift:708-723`：
   - 用 `minContent / imageSize` 反推 zoom 下限：`max(minMagW, minMagH, Constants.minMagnification)`。
   - 僅在 `shouldResizeWindowToMatchImage()` 為 true、非連續捲動時生效；否則回 `Constants.minMagnification (=0.1)`。
4. `effectiveMinMagnification()` — `ImageViewController.swift:726-728`：`max(scrollView.effectiveMinMagnification(), effectiveWindowResizeMinMagnification())`；為所有 clamp（`setMagnificationCentered`、`zoomOut`）共用的入口（`:702-703`、`:1110-1111`）。這符合 CLAUDE.md「resizeToFitImage clamps to effective minimum」的敘述。

### 資料流總結
```
image + viewport
 └─ FittingCalculator (shrink=on/stretch=off) → fittedMagnification
     └─ applyFitting / fitOnScreen → setMagnificationCentered(clamp by effectiveMinMagnification)
         └─ scheduleResizeToFitAfterZoom (gate: shouldResizeWindowToMatchImage)

                 └─ ImageWindowController.resizeToFitImage
                     · upper clamp: screen.visibleFrame

```
